# v0.4.1 P0：独立远程桥与权限状态

实现与主机检查日期：2026-11-01。尚未推送、正式构建、发布或完成本版本真机验收。

## 故障与修复目标

用户确认 vivo V2156FA / Android 11 在掌心窗进入后台后直接关闭系统无障碍开关。此问题列为 P0。用户确认的是开关关闭这一事实；目前没有能定位 vivo 内部关闭策略的系统日志。

普通应用不能静默重开无障碍。本版本让远程桥、Curbox Binder、截图和手势各自判断能力，降低开关关闭对远程通信的影响。

| 能力 | 条件 |
| --- | --- |
| 远程桥 | 用户已启动服务、连接配置有效、系统允许前台服务运行；不要求掌心窗无障碍 |
| Curbox | 本地 Binder 连接及 Curbox 授权有效；Curbox 自身执行权限仍由 Curbox 管理 |
| 手势、节点读屏 | 掌心窗无障碍开关开启且服务已连接；手势另需 Android 7+ |
| 无障碍截图 | 无障碍已连接，且 Android 11+ |
| MediaProjection 截图 | 用户主动授予的录屏会话仍有效；无需掌心窗无障碍 |

录屏授权不存盘，进程死亡、重启、系统撤销或升级后不能恢复旧会话，必须由用户重新授权。手机的“授予录屏截图权限”按钮和系统通知中的“结束截图授权”管理这一独立会话。远程命令不能代替用户批准系统录屏授权。

## 行为变化

- 移除“启动远程桥必须先连接无障碍”的页面门槛；从私有配置恢复服务器和凭据。
- 保留 START_STICKY，恢复启动先检查主动停止标记。开机、应用更新、页面恢复和系统 Job 共用恢复入口；系统限制导致启动失败时记日志，交由后续系统调度或用户处理。
- 主动停止先保存标记，再取消 Job、轮询及 Curbox 重连；截图录屏会话可独立结束。用户在前台查看 Curbox 时可以重新建立查询连接，离开已停止的桥页面后不继续后台重连。
- 状态心跳约 30 秒一次，命令轮询保留配置及 1.5 秒下限。网络失败按指数退避并加入抖动，上限 60 秒；网络恢复通知合并轮询。命令工作与轮询线程分开，繁重用量采集合并并缓存 30 秒。
- 分别上报本地循环、取命令成功、状态上传成功的时间。401/403 明确显示鉴权错误，不把 HTTP 失败记成成功同步；响应读取异常不再吞掉，网络流和连接在异常路径上也会关闭。
- Curbox 重连先释放旧绑定，使用连接代次丢弃过期结果；实际读取成功才重置退避。状态超过 60 秒按未知处理，不把旧专注状态当成实时结果。
- Binder 工作仅一个线程、无排队，等待结果最多 4 秒。超时无法保证终止已发出的远端事务，因此写命令只报告未确认，不自动重放，也不无限创建替代线程。
- 带 ID 的写命令先持久记录收据再执行；重复 ID、缺失 ID 或记录失败时拒绝执行。收据保留窗口为 7 天，最多 5000 条；达到上限时拒绝新写命令，避免删除有效收据造成重复执行。只读查询不占用收据配额。
- 无障碍区分 disabled、disconnected、connected、unknown。静态实例存在不等于系统开关开启；读取失败不冒充关闭。旧界面数据断开后清空或不作为实时数据上报。
- MediaProjection 的画面回调与网络上传分开，慢网络不占用授权撤销回调线程。截图合并为单个请求，超时后允许用户重试；处理行填充及末行没有填充的数据布局。
- 电池优化入口逐级回退到豁免列表、应用详情和系统设置。vivo 引导逐级尝试厂商页面、系统电池页面、应用详情及系统设置；页面不可用时继续回退。自启动开关显示需人工确认。
- 远程解除限制仍默认关闭；没有修改任何真实 Curbox 分组，也没有下发本版本的真机限制命令。

## 检查结果与复现

编译检查需要 JDK 17、Android SDK platform 34、build-tools 34.0.0，以及 Python 3：

```sh
python3 android/check.py --sdk "$ANDROID_HOME" --jdk "$JAVA_HOME"
```

输出仅写入 android/build/check 下的独立运行目录，该目录由现有 gitignore 排除。编译检查采用资源目录输出，不创建可安装 APK，不调用签名工具，也不需要签名秘密。

本地检查结果：

- Android 全部资源编译、Manifest/资源链接、AIDL：通过。
- 同一 JDK javac 后端编译 25 个 Android Java 源文件（含生成代码）：通过。
- 140 项主机断言（含边界遍历）：通过。此数字不是 140 次真机测试。
- 复用本会话已有截图契约脚本，对当前分支后台运行 2 项本机集成测试：鉴权上传后读回原图、无 Token 读取返回 403，均通过。该外部脚本未混入仓库。
- MCP JavaScript 语法与差异空白检查：通过。
- 编译有 source/target 11 与 JDK 17 的选项警告，以及使用既有弃用 API 的提示，没有源码编译错误。Windows 命令行 javac 曾在关闭 SDK ZipFS 时打印 AccessDeniedException 却返回 0；检查脚本明确拒绝这种假成功，并改由短命编译 API 进程完成复核。

## 发布前剩余验证

1. 正式 APK 的 DEX、归档、原签名证书比对及覆盖安装尚未执行。
2. vivo 真机上，无障碍关闭时远程桥及 Curbox 查询持续可用、MediaProjection 有效时手动截图上传、授权撤销后单独提示，仍需验证。
3. 后台/熄屏 5、15、30 分钟，断网重连、开机/更新恢复、主动停止不自行拉起，仍需验证。
4. Curbox 自身权限正常时再核验仅抖音组的短时拦截与自然到期恢复；不会自动选择或改动其他组。

前台服务、电池豁免与 START_STICKY 不能保证阻止 vivo 禁用无障碍或强停应用。Binder 若长期卡住，有限工作线程会保持占用；需要人工恢复应用或 Curbox，不会为恢复而自动重放未知写命令。已取走命令若发生进程死亡，也需要先查询真实状态再决定后续操作。

现有 Render 服务绑定同一分支，后续推送可能连带触发服务自动重部署。本次未推送，因此没有触发该行为；批准推送前需要把这项影响一并纳入发布安排。
